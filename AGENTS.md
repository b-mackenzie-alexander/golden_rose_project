## Engineering workflow
- **Operating reality:** Golden Rose is maintained by one independent developer. There is no standing human review team, CODEOWNER quorum, second administrator, or on-call security staff. “Independent review” means a fresh agent/session quality review unless a named human is actually available; it must never be represented as independent-human authorization. Plans must not require unavailable people or block source work on fictional multi-party governance. The accepted solo-maintainer concentration remains a High residual risk with honest compensating controls.
- **Delivery priority:** The immediate operational objective is a durable `develop` environment that can evolve toward production and that a human can open, exercise, and critique now. Human visibility is a requirement, not an optional later gate. Human browser, accessibility, language, and workflow evidence follows target creation; it cannot be a prerequisite to creating the target.
- **Gate budget:** For private fictional-synthetic `develop`, default to one bounded approval packet covering the exact precheck → Terraform plans/applies → secret preparation → migration → service activation → tester access → automated qualification sequence. Plan inspection still fails closed on deletes/replacements, public database exposure, broad IAM, secret leakage, or out-of-scope actions, but ordinary commands/readbacks must not become separate multi-day approval ceremonies. Split approvals again only for live data, production, destructive recovery, or a materially different authority boundary.
- Keep live/client data and production separately gated, but do not make production-grade governance, attestations, backup/restore qualification, or handoff controls prerequisites for the synthetic `develop` target unless they mitigate a concrete present risk.
- Prefer the smallest reversible path that unlocks a roadmap item or human feedback. Challenge or defer controls that do not materially reduce risk for the current private synthetic scope. A planning/review loop must not continue merely to eliminate the standing solo-maintainer High or perfect a later production boundary.
- Plan → approval → coding → fresh agent review → PR/CI → protected promotion. Human review is added only when an identified human and a running review surface exist.
- Plans operate at outcome scale: each accepted plan should normally cover multiple roadmap items and may authorize several ordered implementation PRs. RED → GREEN nodes remain small inside coding and do not each require a new planning cycle.
- Keep each PR coherent and reviewable, but return to planning only for a material architecture/trust/data/identity/vendor/schema/cloud-authority change, an assumption-invalidating Blocker/High, infeasible decomposition, or user/client feedback that changes the target workflow.
- Hazardous authority remains explicit, but one approved private-synthetic deployment packet may bundle its ordered non-production steps and readbacks. Separate approvals remain mandatory for live-data admission, production promotion, destructive recovery/state editing, unreviewed IAM expansion, or actions outside the packet's exact allowlist.
- Before coding, read the living docs and re-baseline Git state with explicit approval for terminal/Git actions.
- Use a valid branch prefix: `feat/`, `fix/`, `docs/`, `chore/`, `hotfix/`, `security/`, `ci/`, `test/`, `refactor/`, or `spike/`.
- Implement narrowly, with tests first where code is introduced. Run relevant quality/security checks and `git diff --check` after changes when terminal approval is granted.
- Update `CURRENT_WORK.md`, `ROADMAP.md`, and `NOTES.md` after material planning/implementation/review milestones; update technical/security/decision docs when their contracts change.
- **Handoff delivery lock:** Every active handoff must begin with the actual staffing model, the current human-visible runtime outcome, the one-packet gate budget, the exact next executable action, and a “do not regress” list. A receiving session must treat production-only findings as deferred unless they map to a named current-target stop condition. If any continuity surface disagrees, this delivery lock and the newest accepted ADR/plan control until the drift is repaired.
- Never commit secrets, client personal data, raw exports, production data/backups, or unreviewed generated artifacts.
